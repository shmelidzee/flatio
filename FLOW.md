# FLOW — Flatio Development Flow

Два слоя агентов. Верхний превращает твоё мышление в задачи.
Нижний превращает задачи в код.

```
┌─────────────────────────────────────────────────────────────────┐
│  ТВОЁ МЫШЛЕНИЕ — Notion                                          │
│  Бизнес-требования · Функциональные требования · Roadmap         │
│  Источники данных · Модель данных · Открытые вопросы             │
└────────────────────────┬────────────────────────────────────────┘
                         │ агенты читают как контекст (Notion MCP)
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│  ПРОДУКТОВЫЙ СЛОЙ                                                │
│                                                                  │
│  /analyst "идея"   → product-analyst                            │
│     исследует рынок, проектирует решение,                        │
│     обновляет страницы Notion (после твоего ✅)                   │
│                                                                  │
│  /pm decompose     → product-manager                            │
│     читает Notion, сверяет с GitHub Issues,                      │
│     создаёт атомарные issues с AC (после твоего ✅)              │
│                                                                  │
│  /task "описание"  → product-manager                            │
│     быстрое создание одной задачи (после твоего ✅)              │
└────────────────────────┬────────────────────────────────────────┘
                         │
               ╔═════════╧═════════╗
               ║  ТВОЙ ГЕЙТ  ✅    ║  ты апрувишь требования
               ║                   ║  и смотришь issues
               ╚═════════╤═════════╝
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│  ИСПОЛНИТЕЛЬНЫЙ СЛОЙ                                             │
│                                                                  │
│  /pipeline N  → оркестратор                                     │
│     software-engineer  — пишет код                              │
│       ↓                                                          │
│     quality-assurance-engineer  — тесты после каждого коммита   │
│       ↓ зелёный                                                  │
│     technical-reviewer  — жёсткое code review                   │
│     security-engineer   — security review (параллельно)         │
│       ↓ approved                                                 │
│     PR готов → СТОП: ты мержишь                                  │
│                                                                  │
│  /status      — прогресс milestone                              │
│  /review N    — ревью конкретного PR                            │
│  /security N  — security проверка PR                            │
└────────────────────────┬────────────────────────────────────────┘
                         │
               ╔═════════╧═════════╗
               ║  ТЫ МЕРЖИШЬ PR    ║
               ╚═════════╤═════════╝
                         │ после merge
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│  ЗАМЫКАНИЕ ПЕТЛИ                                                  │
│                                                                  │
│  /sync        → technical-writer обновляет docs/ и CHANGELOG    │
│               → product-manager обновляет Roadmap в Notion      │
│                                                                  │
│  /release N   → qa-full + deploy + закрытие milestone           │
└─────────────────────────────────────────────────────────────────┘
```

---

## Типичные циклы

### Цикл «новая фича из головы»
```
идея
  → /analyst "добавить аналитику цен по районам"
  → обсудили, апрувнул требования
  → /pm decompose
  → проверил issues, апрувнул
  → /pipeline <N>
  → посмотрел PR, смержил
  → /sync
```

### Цикл «быстрая задача»
```
/task "настроить springdoc для Swagger UI"
  → апрувнул issue
  → /pipeline <N>
  → смержил PR
  → /sync
```

### Цикл «релиз milestone»
```
/status            — проверить что все issues закрыты
/release 1         — QA full + деплой + закрытие milestone
```

### Цикл «только ревью»
```
/review 42         — technical reviewer на конкретный PR
/security 42       — security проверка параллельно
```

## Принципы

**Продуктовый слой НЕ пишет код.**
Его выход — апрувнутые требования в Notion и issues в GitHub.

**Исполнительный слой НЕ принимает продуктовых решений.**
Его вход — готовый issue с Acceptance Criteria.

**Человеческий гейт между слоями обязателен.**
Агенты готовят, ты решаешь. Две точки где нужен ты:
1. Апрув требований и issues (между слоями)
2. Merge PR (после исполнительного слоя)

**Петля замыкается через /sync.**
После каждого merge — синхронизация документации и Notion.
Дрейф статусов не копится.

## Все команды

| Команда | Слой | Что делает |
|---------|------|-----------|
| `/analyst "идея"` | Продуктовый | Исследует рынок, обновляет требования |
| `/pm decompose` | Продуктовый | Декомпозирует требования на issues |
| `/pm status` | Продуктовый | Статус issues в milestone |
| `/task "..."` | Продуктовый | Создать одну задачу |
| `/pipeline N` | Исполнительный | Весь цикл от issue до PR |
| `/dev N` | Исполнительный | Только разработка |
| `/qa` | Исполнительный | Быстрые тесты после коммита |
| `/qa-full N` | Исполнительный | Полное QA перед milestone |
| `/review N` | Исполнительный | Code review PR |
| `/security N` | Исполнительный | Security review PR |
| `/status` | Утилита | Прогресс текущего milestone |
| `/sync` | Замыкание | Документация + Notion после merge |
| `/release N` | Замыкание | QA full + деплой + закрытие milestone |
| `/deploy` | Инфраструктура | Деплой на Railway |
| `/docs N` | Инфраструктура | Обновить документацию вручную |
