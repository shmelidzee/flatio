# /pipeline

Оркестратор исполнительного слоя. Проводит issue через весь цикл разработки до PR.

## Использование
```
/pipeline [issue-number]
```

## Примеры
```
/pipeline 42       — провести issue #42 через весь цикл
/pipeline          — взять следующий issue по приоритету
```

## Автономный режим

**Всё общение идёт в GitHub. В терминал выводится только финальная ссылка на PR.**

Оркестратор никогда не останавливается чтобы задать вопрос владельцу продукта в чате.
Любые решения, предположения, эскалации — документируются в виде комментариев к Issue или PR,
и работа продолжается автономно.

Единственная легитимная точка остановки — PR готов к merge.

## Что делает

Читает `.claude/agents/software-engineer.md`, `.claude/agents/quality-assurance-engineer.md`,
`.claude/agents/technical-reviewer.md`, `.claude/agents/security-engineer.md`
и выполняет их по цепочке:

```
Issue (ready, не blocked)
  ↓
[software-engineer] создаёт ветку, пишет код, коммитит
  ↓
[quality-assurance-engineer] быстрый режим
  ├── ❌ красный → [software-engineer] фиксит → [qa] снова
  │   (макс 3 итерации, потом эскалация → комментарий в Issue, pipeline завершается)
  └── ✅ зелёный
        ↓
[technical-reviewer] + [security-engineer] — параллельно
  ├── Request Changes / CRITICAL+HIGH
  │     ↓
  │   [software-engineer] читает все comments из PR, правит код
  │     ↓
  │   [quality-assurance-engineer] снова — тесты после правок
  │     ├── ❌ красный → [software-engineer] фиксит → [qa] снова
  │     └── ✅ зелёный
  │           ↓
  │         [technical-reviewer] перепроверяет свои замечания
  │         [security-engineer] перепроверяет если были его замечания
  │           ├── ещё замечания → повторить петлю (макс 3 итерации суммарно)
  │           └── оба Approved
  └── оба Approved
        ↓
PR готов → вывести ссылку в терминал → СТОП
```

## Эскалация

Если после 3 итераций проблема не решена — оркестратор **не спрашивает в терминале**.
Вместо этого:
1. Оставить комментарий в PR с описанием блокера:
```
⚠️ Требуется решение PO

Pipeline завершён после 3 итераций. Нерешённые проблемы:
1. [агент] — [проблема] — [почему не удаётся исправить автономно]
2. ...

Смержи PR после ручного решения, или закрой его и создай новый Issue.
```
2. Завершить pipeline.

## Финальный вывод в терминал

Единственное что выводится в терминал после завершения:

```
✅ PR #N готов: https://github.com/…/pull/N
```

или при эскалации:

```
⚠️ PR #N заблокирован — подробности в PR: https://github.com/…/pull/N
```

## После merge
Запусти `/sync` — обновит документацию и статусы.
