# Roofly

Агрегатор объявлений о недвижимости. Собирает объявления из внешних источников, нормализует их к единому формату и предоставляет пользователям единый поиск, подписки, историю цен и аналитику рынка.

Первый рынок — Беларусь. Архитектура страну-агностична: источники, валюты и языки — подключаемые конфигурации, не константы в коде.

## Технологический стек

- **Java 25** (LTS) — виртуальные потоки (Project Loom) для I/O при опросе источников
- **Spring Boot 4.0** (Spring Framework 7, Spring Security 7, Hibernate 7)
- **PostgreSQL** — основная БД
- **Redis** — кэш, rate limiting, хранение refresh-токенов для отзыва
- **Elasticsearch** — полнотекстовый поиск с языковой конфигурацией по источнику
- **Maven** — сборка

### Тестирование
- JUnit 5 + Mockito — unit-тесты
- Testcontainers — интеграционные тесты с реальными PostgreSQL и Redis
- Spring Boot Test slices (`@WebMvcTest`, `@DataJpaTest`)

### Безопасность
- Spring Security 7 + JWT (access + refresh tokens)
- Отзыв refresh-токенов через Redis
- Пароли — bcrypt/argon2
- Rate limiting через Redis (bucket4j или кастомный интерцептор)

## Архитектурные принципы

**Источник — это коннектор.** Каждый источник данных изолирован в своём коннекторе с общим интерфейсом. Изменение одного источника не затрагивает другие. Ядро не знает о деталях конкретных площадок.

**Upsert по ключу `(external_id, source)`.** Новые объявления вставляются, существующие обновляются. При изменении цены — запись в таблицу истории цен.

**Объявление без источника не существует.** У каждого объявления всегда указан источник и ссылка на оригинал (BR-4, BR-7).

**Агрегируем только публичные данные.** Если источник запрещает автоматический сбор через robots.txt или ToS — источник не подключается (BP-1, BP-3).

**Мультистрановость закладывается сразу.** Страна, валюта, язык — атрибуты источника. Полнотекстовый поиск конфигурируется по языку источника.

## Структура модели данных (ключевые сущности)

- `listing` — объявление (external_id, source, тип сделки, тип недвижимости, цена, площади, адрес, координаты, статус, extra_data)
- `listing_price_history` — история изменений цены объявления
- `source` — источник (название, страна, валюта, язык, интервал синка, статус, enabled)
- `user` — пользователь (email, тариф: FREE/PREMIUM/PRO, роль: USER/ADMIN)
- `subscription` — подписка на фильтр поиска
- `favorite` — избранные объявления пользователя

Источник объявления может иметь тип `OWN` (для будущей поддержки собственных объявлений) — не реализовывать сейчас, но тип заложить.

## Источники данных (Беларусь)

| Источник | Интеграция | Интервал | Статус |
|---|---|---|---|
| Onliner | JSON API | 15 мин | Первый коннектор |
| Realt.by | JSON API / HTML | 15 мин | Следующий |
| Kufar | JSON API | 30 мин | После отладки пайплайна |

Не подключать источники-агрегаторы (например, Morizon) — они сами агрегируют других, что даст дубли.

## Бизнес-правила (не нарушать)

- Не проводить сделки, не принимать оплату за аренду/покупку (OOS-2)
- Не связывать покупателя с продавцом внутри продукта (OOS-3)
- Не хранить персональные данные продавцов сверх опубликованного (BP-5)
- Перед подключением источника — проверять robots.txt и ToS

## Тарифы

`FREE` / `PREMIUM` / `PRO` — разграничение доступа к функциям через тарифный план пользователя. Логика ограничений реализуется на уровне сервиса, не в контроллерах.

## Админ-панель

Доступна только пользователям с ролью `ADMIN`. Работает через выделенные защищённые `/admin/**` эндпоинты, не напрямую с БД.

Функции: dashboard (метрики), управление источниками (вкл/выкл/синк без деплоя), мониторинг синхронизаций, управление объявлениями (статус, дедупликация), управление пользователями (тариф, блокировка).

## Что намеренно вне скоупа сейчас

- Собственные объявления пользователей
- Встроенный чат/звонки с продавцом
- Ипотечный брокер, юридические консультации
- CRM для риелторов
- Mobile-клиент (пост-MVP: Flutter или нативные Swift/Kotlin)
- Web-клиент (пост-MVP: React или Vue)
